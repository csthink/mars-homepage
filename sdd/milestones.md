## 规划基线

本计划据 spec.md@r1 构造，只安排其范围内的交付。全部任务放在一个 Milestone：三项改进规模都小，拆分 Milestone 不带来额外的判断点。会改变页面外观的任务先经低保真设计、再经高保真设计，各由 Mars 冻结后才可施工；不改变外观的任务不依赖设计。编号只表达身份，不表达顺序。

## Milestone 条目

### M-01 个人主页首批改进

- 阶段目标：访问者经主导航到达作品页并可切换深色模式，站点信息集中在一个配置文件，每项改进后站点构建与检查都通过。
- UI 变更：有
- UI lineage：新起点：以现有站点页面为继承对象，由本 Milestone 的低保真与高保真设计确立
- 任务清单：
  - design-t0 作品页与深色模式开关的低保真设计：页面结构、导航入口与切换控件位置，允许自包含单文件 HTML · 类型：低保真 · Spec 引用：spec.md@r1 FR-1、FR-2、FR-3、FR-7 · 依赖：无
  - design-t1 作品页与深色模式的高保真设计：继承低保真骨架并确定配色与视觉细节 · 类型：高保真 · Spec 引用：spec.md@r1 FR-1、FR-3、FR-7 · 依赖：design-t0
  - feature-t0 新增作品页并接入主导航 · 类型：前端 · Spec 引用：spec.md@r1 FR-1、FR-2、FR-7 · 依赖：design-t1
  - feature-t1 深色模式开关并补一条站点检查 · 类型：前端 · Spec 引用：spec.md@r1 FR-3、FR-4、FR-7 · 依赖：design-t1
  - feature-t2 站点标题、描述与社交链接抽成配置文件并更新 README · 类型：前端 · Spec 引用：spec.md@r1 FR-5、FR-6 · 依赖：无
- 验收条件：
  - 从任一页面经主导航一次点击到达作品页，作品页条目的名称、说明与链接齐全（spec.md@r1 SC-1）。
  - 任一页面可切换浅色与深色配色并在后续页面保持，缺少切换控件时站点检查失败（spec.md@r1 SC-2）。
  - 修改配置文件后重新构建，所有页面的站点信息随之改变，README 写明配置文件的位置与字段（spec.md@r1 SC-3）。
  - 构建命令与检查命令都通过，既有检查项仍在（spec.md@r1 SC-4）。
  - 低保真与高保真设计各自由 Mars 冻结，作品页与深色模式的实现与高保真设计一致。

## 跨 Milestone 依赖与调度

只有一个 Milestone，没有跨 Milestone 依赖。design-t0 与 feature-t2 没有依赖，可先选定；design-t1 在低保真设计冻结后选定；feature-t0 与 feature-t1 在高保真设计冻结后选定。依赖满足的候选中先做哪一个由 Mars 决定；同时在做的任务数按本仓配置的并发上限。

## 反思

### 必须现在定

- 两个设计任务排在会改变外观的两个功能任务之前：不定则作品页与深色模式可能在外观未确认时施工，返工落到实现上。
- 站点配置任务不依赖设计：不定则它会被无关的设计进度阻塞。

### 同类潜在 bug 一并防止

- 失效类「外观未经确认就施工」：由功能任务依赖高保真设计、高保真设计依赖低保真设计防住。
- 失效类「任务范围超出 spec」：由每个任务行的 Spec 引用只指向 spec.md@r1 已定义条目防住。

### 可接受残留（分级）

- 低：两个设计任务使首批改进的步骤增多，接受，理由 = 页面外观变化需要先经设计确认，这是本仓采用的最低要求。
