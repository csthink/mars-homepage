## 产品目标与用户问题

与 proposal 一致：访问者一次导航即可看到 Mars 的作品，并可在浅色与深色配色之间切换；Mars 在一处修改站点标题、描述与社交链接；每次改动后站点自带的构建与检查都通过。要解决的问题是访问者没有作品入口、暗光环境下只有浅色配色，以及站点信息写死在页面代码里。

## In Scope

- **S-1** 作品页：列出作品并从主导航到达。
- **S-2** 深色模式开关：页面配色可在浅色与深色之间切换，并由站点检查覆盖。
- **S-3** 站点配置：站点标题、描述与社交链接由单一配置文件提供，README 说明修改方式。
- **S-4** 设计先行：作品页与深色模式的外观先经低保真设计、再经高保真设计确认，然后实现。

## Out of Scope

- **O-1** 文章正文、文章详情页与内容集合。
- **O-2** 移动端导航折叠。
- **O-3** 评论、搜索、访问统计以及需要服务端或账户的功能。
- **O-4** 部署方式、托管平台与域名配置的改变。

## Functional Requirements

- **FR-1** 站点提供作品页，列出作品条目；每个条目包含名称、一句说明与指向作品的链接；页面有标题。
- **FR-2** 每个页面的主导航包含指向作品页的链接；位于作品页时该导航项标记为当前页。
- **FR-3** 每个页面提供浅色与深色配色的切换控件；切换后当前页面配色随之改变，在同一浏览器中后续打开的站点页面沿用所选配色。
- **FR-4** 站点检查新增一项：构建产物中的每个页面都包含深色模式切换控件；任一页面缺少时检查失败并指出该页面。
- **FR-5** 站点标题、描述与社交链接由单一配置文件提供；页面布局与各页面从该文件读取，不在页面代码中另行写死这些值。
- **FR-6** README 写明站点配置文件的位置、各字段含义以及修改后重新构建的方式。
- **FR-7** 作品页与深色模式的外观以已冻结的高保真设计为依据；高保真设计继承已冻结的低保真设计。

## Non-functional Requirements

- **NFR-1** 站点保持纯静态输出，不引入服务端、账户或第三方追踪。
- **NFR-2** 站点的构建命令与检查命令在每项改进完成后都通过；检查项只增不减。

## 核心旅程与产品约束

访问者从首页经主导航进入作品页，浏览条目后跳到作品本身；任何页面上都可以切换配色，切换结果在后续页面保持。Mars 修改配置文件并重新构建后，所有页面显示新的站点信息。

- **C-1** 首页、关于与文章占位页的内容与访问路径保持不变，除非某项改进明确需要调整导航或布局。
- **C-2** 既有检查项（每页有标题、站内链接有效）保留，不得为使检查通过而删除或放宽。
- **C-3** 不改变部署方式与构建命令、检查命令的入口。

## MVP 整体成功条件

- **SC-1** 从任一页面经主导航一次点击到达作品页，作品页每个条目的名称、说明与链接都在，站内链接经站点检查有效。
- **SC-2** 在任一页面可切换浅色与深色配色，切换结果在后续页面保持；删去任一页面的切换控件时站点检查失败。
- **SC-3** 修改配置文件中的站点标题、描述或社交链接并重新构建后，所有页面随之改变，页面代码无改动；README 写明配置文件的位置与字段。
- **SC-4** 三项改进完成后，构建命令与检查命令都通过，既有检查项仍在。

## 本 spec 不决定的事

- 作品条目的具体内容与数量：由作品页任务的定义承载。
- 深色配色的具体取值、首次访问是否跟随系统配色偏好：由高保真设计与深色模式任务的定义承载。
- 站点配置文件的格式与位置：由站点配置任务的定义承载。
- 设计的表现形式与存放位置：由低保真与高保真两个设计任务承载。

## 反思

### 必须现在定

- 深色模式的选择在后续页面保持（FR-3）：不定则在多页静态站点中切换每次换页都会复原，功能不可用。
- 新增检查只核对切换控件是否在每个页面（FR-4）：不定则深色模式任务的「补一条检查」没有可判的完成标准。

### 同类潜在 bug 一并防止

- 失效类「为让检查通过而削弱检查」：由 C-2 与 NFR-2 的检查项只增不减防住。
- 失效类「站点信息在布局与页面中重复写死」：由 FR-5 的单一来源防住。

### 可接受残留（分级）

- 低：首次访问是否跟随系统配色偏好留给设计与任务定义，接受，理由 = 不影响切换与保持两项可判结果。
- 低：检查只核对切换控件存在，不核对配色取值，接受，理由 = 配色由高保真设计确认，静态检查难以判断视觉效果。
