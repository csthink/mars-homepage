# 从文本核实状态（verify-from-text）

> 中立能力正本条目（布局权威 §5.2 落点；出生于 gov-t26 施工批）。
> 来源 = legacy:KB-28 工作方法面复审，处置裁定 = `mechanisms/handoff-protocol/HarnessPlane_Handoff_Protocol_Design_v1.md` §10.3（FROZEN r1）：
> 方法的可协议化内核（自报恒为声明、承重声明配可机械比对锚点、状态从文本核实）已由该协议 §3.1 / §4.2 机械承载；
> 本条目承载其余执行纪律——它约束执行行为，不是记录文法，也不新设任何机械看守。

## 共同根因

把「我刚做了什么」当事实来源，而不是把「文件现在是什么样」当事实来源。
三个典型表现：写超范围结论是写下意图而非条文实际允许的；只改一处是认为「刚改过就已改好」；
新义务未履行是认为「加了就成立」而不核其依赖。三者皆为从记忆与意图推断状态，违反点集中在总结那一步。

## 两个高发缺陷形态

1. **把「有条件成立」写成「无条件成立」**：正文定得对，总结句把限定条件丢了。
   高发位置 = 节末总结、残留表、自检节这三类压缩表达处。机制 = 准确说法是长条件句、
   漂亮说法是短断言，写散文时默认取后者。
2. **改一处不回头核该改动的全部后果**，两个子形态：
   同一句话散在多处只改首次出现处；改动在别处产生了义务而未履行（新读一个字段却没把它加进接口、
   新立一条规则却存在结构上永远无法满足它的对象、改分组后计数与实际不符）。

## 现行方法：结构穷举核对

修改或总结涉及某实体的断言时：

1. 全文搜**被讨论实体的名字**（它必然出现、与措辞无关），不搜自己记得的整句或自选判别词——
   搜索键来自记忆的方案已三次实测失效：凡遗忘者，搜索原理上即不可达。
2. 命中逐条分类为「合规 / 显式沿革 / 待查」，**要求待查为零**。
3. 计数一律用机械命令核（如 `grep -c`），不心算、不引用记忆值。

## 改动义务清单

每次改动后，先列出它给别处产生了什么义务，再逐条核实履行：

- 同一断言的其余出现处是否同批更新；
- 新引用的字段 / 文件 / 规则是否真的存在并可满足；
- 上游声明的计数、闭集、顺序是否仍与实物一致；
- 引用本处的外部位置（标题、路由表、总数句）是否仍然成立。

## 自检的诚实规则

不给「文内已一致、无相反声称」类结论——对自己覆盖面的估计一贯偏高，且抓住遗漏的
历来是异源评审方而非作者自检。自检节只写明用什么方法核的与该方法已知的局限。

## 已登记、尚未落地的两个方向

- 穷尽枚举「保证性句子」的结构位置（节末总结、残留表每行、自检节每条），
  逐句核「什么条件下成立 / 谁保证 / 有没有例外」，而非搜关键词。
- 把「改动义务清单」由自觉步骤升级为可核对工件。
